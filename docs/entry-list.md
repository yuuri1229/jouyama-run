# エントリーリストの自動反映（設定手順）

エントリー管理シートで入金ステータスを「振込済み」にすると、
1時間以内にサイトの [エントリーリスト](https://niigata24h-run.com/entries/) に掲載されます。

## しくみ

```
エントリー管理シート（URL非公開のまま）
   │  サービスアカウント（閲覧のみ）で読み取り
   ▼
GitHub Actions（1時間ごと＋手動実行）
   │  「振込済み」の行の公開項目だけを抜き出してサイトをビルド
   ▼
GitHub Pages（/entries/）
```

- シートは一般公開しません。Google Cloud の「サービスアカウント」というロボット用の
  アカウントにだけ **閲覧者** として共有し、その鍵を GitHub の Secrets に保管します。
- サイトに出るのは **出走カテゴリ・ゼッケンNo.・氏名・フリガナ・居住地・性別** だけです。
  メールアドレス・電話番号・入金情報などの列は、読み取り直後に捨てています
  （`scripts/fetch-entries.mjs`）。
- 参加者の一覧はリポジトリには保存しません（公開リポジトリのため）。ビルドのたびに
  シートから作り直します。Actions のログにも氏名などは出しません（件数だけ）。
- `/entries/` は検索エンジンに載らない設定（noindex）にしています。
- 鍵を登録するまでは、これまでどおり外部のスプレッドシートへの案内を表示します。

## 初回の設定（1回だけ・約15分）

### 1. サービスアカウントを作る（Google Cloud）

1. <https://console.cloud.google.com/> にシートの持ち主のGoogleアカウントでログイン
2. 上部のプロジェクト選択 →「新しいプロジェクト」→ 名前は例えば `jouyama-run` で作成
3. 「APIとサービス」→「ライブラリ」→ **Google Sheets API** を検索して「有効にする」
4. 「IAMと管理」→「サービスアカウント」→「サービスアカウントを作成」
   - 名前：例 `entry-list-reader`。ロール（権限）の付与は **不要**（スキップ）
5. 作成したサービスアカウントを開く →「キー」タブ →「鍵を追加」→「新しい鍵を作成」→ **JSON**
   - JSONファイルがダウンロードされます。**これが鍵です。メールやチャットに貼らないでください。**
6. サービスアカウントのメールアドレス（`entry-list-reader@….iam.gserviceaccount.com`）を控える

### 2. 管理シートを共有する

1. エントリー管理シートを開き「共有」
2. 上で控えたサービスアカウントのメールアドレスを追加し、権限を **閲覧者** にする
   （通知メールは送れない旨が出ますが問題ありません）

### 3. GitHub に鍵とシートIDを登録する

リポジトリの **Settings → Secrets and variables → Actions** で、
「New repository secret」から次の2つを登録します。

| 名前 | 値 |
| --- | --- |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | ダウンロードしたJSONファイルの中身をすべて貼り付け |
| `ENTRY_SHEET_ID` | 管理シートのURLの `/d/` と `/edit` の間の文字列 |

管理シートの中に複数のシート（タブ）があり、先頭以外を読ませたい場合だけ、
同じ画面の「Variables」タブで `ENTRY_SHEET_RANGE` にそのタブ名（例：`フォームの回答 1`）を登録します。

登録後、JSONファイルはパソコンから削除して構いません（必要になったら作り直せます）。

### 4. 動作確認

1. **Actions → Deploy to GitHub Pages →「Run workflow」** で手動実行
2. 「エントリーリストを取得」のステップに `掲載 ○ 名（24H ○ / 12H DAY ○ / 12H NIGHT ○）` と出れば成功
3. <https://niigata24h-run.com/entries/> を確認

## 管理シートの読み方

管理シート（エントリー管理【第3回】）は**改変禁止**のため、見出しの名前ではなく**列の位置**で読みます。
サービスアカウントの権限も「閲覧者」だけなので、シートを書き換えることはできません。

| 項目 | 列 | サイトでの扱い |
| --- | --- | --- |
| 入金ステータス | C | `振込済み` の行だけを掲載（前後の空白は無視）。サイトには出さない |
| 出走カテゴリ | D | 「デイ」を含めば12時間走デイスタート、「ナイト」を含めば12時間走ナイトスタート、「24時間」を含めば24時間走に振り分け。**金額は出さない** |
| 氏名 | G | そのまま |
| フリガナ | H | そのまま（詳細モーダルのみ） |
| 性別 | I | そのまま（詳細モーダルのみ） |
| 住所 | K | **住所は出さない**。新潟県内は市町村名（例：新潟市、燕市、弥彦村）、県外は都道府県名（例：東京都）に変換してから掲載（詳細モーダルのみ） |
| ゼッケンNo. | （シートに無い） | カテゴリごとにエントリー順（シートの行順）で自動付番。24時間走 101〜／デイ 201〜／ナイト 301〜。振込済みの人だけで詰めて連番にするため、先にエントリーした人が後から入金すると、後ろの人の番号がずれる。開始番号は `lib/entries.js` の `bibStart` |

- 住所の変換は `lib/residence.js`。区・番地・建物名・郵便番号は必ず捨てます。
  都道府県が書かれていない住所は、新潟県内の市町村名で始まる場合だけ市町村名にし、
  それ以外は推測せず「—」と表示します（ログには件数だけ出ます）。
- 出走カテゴリを判別できない行は掲載せず、ログに件数を出します。
- 列の並びが変わったときは `lib/entries.js` の `ENTRY_SHEET.columns` を書き換えます。

## 反映の間隔

- 自動：**1時間ごと**（毎時23分ごろ。GitHub の混雑で数分〜十数分遅れることがあります）
- すぐ反映したいとき：Actions →「Deploy to GitHub Pages」→「Run workflow」

間隔を変えるときは `.github/workflows/deploy.yml` の `cron` を書き換えます。
大会後に更新を止めるときも同じ場所です（日1回 `0 20 * * *` に戻すなど）。

## 鍵の管理

- 鍵が漏れた疑いがあるときは、Google Cloud のサービスアカウント →「キー」で該当の鍵を削除し、
  新しい鍵を作って `GOOGLE_SERVICE_ACCOUNT_JSON` を登録し直してください。
- サービスアカウントの権限はシートの「閲覧者」だけなので、鍵でシートを書き換えることはできません。
